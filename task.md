# IPtable — оформление сводки адресов на странице подсети

## Цель и ожидаемый результат

Привести блок сводки над IP-таблицей к приложенному дизайну. На широком экране это одна светлая панель с мягким скруглением и тенью, разделённая на пять секций. В каждой секции слева находится иконка в цветной плашке, справа — подпись над крупным числом. Задача относится к блоку `.project-summary` на странице проекта. Таблица адресов, панель деталей IP и обзор сети на главной странице остаются в текущем оформлении.

## Состав панели

| Порядок и подпись в RU | Переменная Jinja | Иконка | Цвет секции |
| --- | --- | --- | --- |
| Всего | `total_count` | Стопка слоёв | Белый фон, голубовато-серая плашка |
| Занято | `filled_count` | Силуэт пользователя | Белый фон, голубовато-серая плашка |
| Пусто / скрыто | `empty_count` | Перечёркнутый глаз | Белый фон, голубовато-серая плашка |
| Ping OK | `online_count` | Галочка в окружности | Светло-мятный фон, зелёные число и иконка |
| Ping NO | `offline_count` | Восклицательный знак в окружности | Светлый персиковый фон, тёмно-оранжевые число и иконка |

Числа на референсе показывают пример. Рендерить фактические значения из текущего контекста и сохранить существующие ключи перевода RU/EN. «Занято» и «Пусто / скрыто» относятся к заполненности ручных полей, Ping — к доступности. Не пересчитывать показатели по видимым строкам текущей страницы и не добавлять непроверенные адреса в Ping NO. Ноль показывать явно.

## Шаги реализации

1. Прочитать `AGENT.md`. В `app/templates/project.html` найти `.project-summary` внутри `.table-filter-form`. Сохранить порядок секций, классы состояний и серверные переменные. Добавить в каждую секцию декоративную SVG-иконку и контейнер для пары «подпись / значение». Использовать `currentColor`, `aria-hidden="true"` и `focusable="false"`. Подписи и числа должны быть настоящим текстом. Сводка остаётся информационной, без кнопок и дополнительных остановок Tab.
2. В `app/static/atlas.css` обновить правила сводки, включая её адаптивные переопределения. Сделать единый внешний контур с тонкой светлой границей, мягкой тенью и общим радиусом. Между секциями — тонкие разделители. Цветные заливки Ping доходят до границ секций. Убрать прежние цветные полоски `::before` у счётчиков. Выровнять плашки, подписи и числа по повторяющейся сетке. Дать длинной подписи больше пространства при необходимости. Цвет подписей приглушённый, основные числа тёмные, шрифт наследуется от приложения. Использовать табличные цифры. Ориентиры для рабочего UI — плашки 36–44 px, значки 18–22 px, подписи 12–14 px, числа 24–30 px. Размеры подогнать к реальной ширине контента, без переноса пустого пространства вокруг панели с референса.
3. На широком экране показать пять секций в один ряд. Если сводка вместе с заголовком и действиями не помещается, выделить ей отдельную строку в верхней части страницы. На узких экранах использовать две колонки внутри общей панели, пятая секция занимает всю последнюю строку. При недостатке места перейти в одну колонку. Сохранить разделители по фактическим границам сетки. Длинные подписи могут переноситься, числа и иконки не должны обрезаться. Сводка не должна порождать горизонтальную прокрутку страницы или заслонять таблицу и её действия.
4. Проверить каскад `styles.css` и `atlas.css`: старые селекторы по тегам внутри `.summary-item` не должны менять стили новых вложенных элементов. При необходимости точечно обновить версию `atlas.css` в базовом шаблоне, сохранив origin-relative URL.

## Файлы и ограничения

- `app/templates/project.html` — разметка пяти секций.
- `app/static/atlas.css` — оформление панели, секций и адаптивность. `app/static/styles.css` использовать для проверки каскада.
- `app/templates/_icons.html` — при переиспользовании общего SVG-макроса добавить только необходимые иконки. Допустимо определить иконки непосредственно в шаблоне сводки.
- `app/templates/base.html` — только версия CSS-ресурса, если потребуется. Новые файлы реализации и зависимости не нужны.

Сохранить `.table-filter-form`, JavaScript-хуки, действия и GET-параметры фильтров, скрытие пустых строк, пагинацию и открытие деталей IP. Запрещено менять серверные расчёты, маршруты, JavaScript, переводы, схему БД, API, права и настройки. Не использовать картинку как фон панели, не подключать удалённые иконки или шрифты, не менять глобальные токены ради этого блока. Текст и числа должны сохранять контраст не ниже 4,5:1. Цвет дополняет текстовые подписи статусов.

## Проверки

Из корня проекта с установленными dev-зависимостями:

```bash
.venv/bin/python -m pytest -q tests
.venv/bin/python -m ruff check app tests
git diff --check
git status --short
```

В браузере проверить 1440×900, 768×1024 и 390×844 в RU и EN. Использовать подсеть с заполненными и пустыми адресами, разными статусами Ping, нулями и многозначными числами. Сверить значения до и после правки при одинаковых данных. Пройти фильтрацию, сброс фильтра, показ скрытых строк и смену страницы. Убедиться, что сводка и таблица отображаются согласно прежней логике, а фильтры и меню остаются доступными. Сделать снимки сводки в контексте страницы на широком и узком экранах.

## Критерии завершения

- На широком экране видна единая панель из пяти секций в порядке референса. У каждой секции есть соответствующая иконка, подпись над числом и нужный цветовой акцент.
- На узком экране видны все пять значений, подписи и числа не обрезаются, горизонтального переполнения страницы нет.
- Реальные значения и локализация сохранены. Таблица и её действия работают как прежде.
- Diff ограничен оформлением сводки и необходимым подключением ресурсов. Автоматические проверки проходят, результат браузерной проверки подтверждён снимками.

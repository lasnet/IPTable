# IPtable

IPtable - веб-приложение для учета занятых IP-адресов в локальных сетях. Проект заменяет Excel-таблицы для инвентаризации сетевых активов: можно создавать папки, заводить проекты-подсети, вести карточки IP-адресов и регулярно проверять доступность адресов через ICMP ping.

## Что умеет проект

- Создание папок/групп для логической организации сетей.
- Создание проектов-подсетей, например `172.16.16.0/24`.
- Автоматическое создание строк таблицы для каждого IP-адреса подсети.
- Ручное заполнение полей `hostname`, `OS`, `type`, `comment`.
- Создание дополнительных пользовательских столбцов для проекта.
- Скрытие незаполненных IP-записей в таблице проекта.
- Общий поиск по папкам, проектам и IP-записям.
- Фоновая проверка доступности IP-адресов через ICMP ping раз в 60 минут.
- Запуск локально через Docker Compose.

## Архитектура проекта

Проект сделан как монолитное веб-приложение:

- `FastAPI` обслуживает HTML-интерфейс, формы, healthcheck и фоновые задачи.
- `SQLAlchemy` описывает модели и работает с базой данных.
- `PostgreSQL` хранит папки, проекты, IP-записи и пользовательские поля.
- `Jinja2` используется для серверного HTML-рендеринга.
- Фоновый ping-worker запускается внутри приложения и проверяет адреса с заданным интервалом.

Отдельный Redis/queue пока не нужен: текущая задача хорошо укладывается в простой фоновой цикл. Если в будущем появятся десятки тысяч адресов, worker лучше вынести в отдельный сервис.

## Настройка `.env`

Скопируйте пример:

```bash
cp .env.example .env
```

Минимально нужно задать надежный пароль БД:

```env
POSTGRES_PASSWORD=replace-with-strong-local-password
```

Основные переменные:

- `APP_PORT` - порт веб-приложения на хосте.
- `DATABASE_URL` - строка подключения SQLAlchemy.
- `PING_INTERVAL_SECONDS` - интервал фоновой проверки адресов.
- `PING_TIMEOUT_SECONDS` - timeout одного ping.
- `PING_CONCURRENCY` - параллелизм ping-проверок.
- `MAX_PROJECT_ADDRESSES` - максимум IP-адресов в одном проекте.
- `ENABLE_PING_WORKER` - включает или выключает фоновую проверку.

## Запуск через Docker Compose

```bash
cp .env.example .env
docker compose up --build
```

После запуска приложение будет доступно:

```text
http://localhost:8000
```

Если в `.env` изменен `APP_PORT`, используйте выбранный порт.

## Запуск без Docker

Для быстрой локальной разработки можно использовать SQLite:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
mkdir -p data
export DATABASE_URL=sqlite:///./data/iptable.sqlite3
export ENABLE_PING_WORKER=false
uvicorn app.main:app --reload
```

Приложение будет доступно на `http://127.0.0.1:8000`.

## Как проверить, что проект работает

1. Откройте `http://localhost:8000`.
2. Создайте папку, например `Office`.
3. Создайте проект с CIDR `172.16.16.0/24`.
4. Откройте проект и убедитесь, что появилась таблица IP-адресов.
5. Заполните `hostname`, `OS`, `type` или `comment` у нескольких адресов.
6. Включите фильтр `Скрыть пустые`.
7. Проверьте поиск через верхнюю форму.
8. Откройте `http://localhost:8000/health` и убедитесь, что вернулся статус `ok`.

## Типичные проблемы и их решение

- `POSTGRES_PASSWORD is required`: скопируйте `.env.example` в `.env` и задайте пароль.
- Приложение не подключается к БД: проверьте `DATABASE_URL`, имя сервиса `postgres` и логи `docker compose logs postgres`.
- Ping всегда показывает offline: контейнеру нужен ICMP-доступ. В `docker-compose.yml` уже добавлен `NET_RAW`, но сеть или firewall могут блокировать ICMP.
- Слишком большая подсеть не создается: увеличьте `MAX_PROJECT_ADDRESSES`, если понимаете нагрузку. По умолчанию стоит защитный лимит.
- Порт занят: поменяйте `APP_PORT` в `.env`.
